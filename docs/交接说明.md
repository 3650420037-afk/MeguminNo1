### 0.3 「两个对话在同一个仓库里打架」——已发生，处理规则如下

**事实**：本仓库**同时有另一个 agent 在同一目标上工作**（它维护
`docs/deck_7eonmol/**` 演示 PPT、`docs/长期目标_结合强度.md` 看板、
`src/scripts/arm_gen_metrics.py`，并且会读取 `docs/任务状态与记忆.md`）。
两边**共用同一个工作目录与同一个 git 仓库**，因此会互相干扰。

**已经真实发生过的三类冲突**

| 类型 | 实例 | 后果 |
| --- | --- | --- |
| **提交被扫入** | 我用 `git add -A -- docs src ...` 把协作者的两个文件提交进自己的 commit 且信息未提及（`f8e3b999`，已推送） | 责任归属混乱 |
| **git 锁冲突** | `.git/index.lock` 被对方占用，我的提交报错；等 3 分钟无 git 进程后判定为陈旧锁才移除 | 提交失败 |
| **状态互相过时** | 对方的看板写着"v9 训练进行中"，而训练已结束 | 接手者被误导 |

**接手者必须遵守的四条**

1. **永远不要 `git add -A`**，也不要 `git add docs src` 这类过宽路径 ——
   **逐个文件显式添加**自己改的那几个。
2. **提交前先 `git status --porcelain` 看一遍**：出现**你不认识的文件**就说明是对方的，
   **不要提交它们**（也不要删除）。
3. **遇到 `.git/index.lock`**：先 `Get-Process git`；**无 git 进程且锁存在 >60 秒**才可删，
   否则等待重试。（我方曾因此失败 3 次。）
4. **改共享文档时先读再改**（对方可能刚改过）；`docs/长期目标_结合强度.md` 的
   「进度日志」**只追加**，不要重写别人的条目；发现对方状态过时，
   **追加一条更正**而不是删改。

**判断"谁写的"最快的方法**
```powershell
git log --oneline -3 -- <文件路径>     # 看最近是谁在改
Get-Item <文件路径> | Select-Object LastWriteTime   # 改动时间是否与你的操作吻合
```

## §6 方法论纪律（血泪换来的硬规则，**违反即出错**）

1. **单种子不下结论**。`ab_docking_compare.py` 在只有 1 个种子时**只输出
   `PROVISIONAL(未证实)`**，不得据此晋级。
2. **噪声尺度**：同臂**重复运行**的 Vina 中位噪声 ≈ **0.14**；**种子间**噪声 ≈ **0.7**。
   判断效应显著必须用后者。我曾据此两次过早宣布改进、两次被第二种子推翻。
3. **必须同时报「原始 Vina」与「配体效率 LE」**，并在两臂尺寸差 >15 % 时警告。
   Vina 与分子大小强相关；只比原始分会把"分子更小"误读成"亲和力更差"。
4. **选点用生成指标，不用验证损失**。本项目多次证明两者背离
   （曾出现 val 1.97→0.77 而生成 QED 0.597→0.408）。
5. **出货目标是 `diversity_w = 0.5`**（`design.py`/`predict.py` 默认注入）。
   A/B 必须先确认评测目标与出货目标同源，否则结论无效。
6. **网格没扫完不下结论**（我曾只凭第一个点就宣布阈值 −0.25 是甜点，被 −0.5 推翻）。
7. **不得使用 `git add -A`** —— 本仓库**有并发写作者**在提交 `docs/deck_7eonmol/**`（演示 PPT），
   且它**正在读取 `docs/任务状态与记忆.md`**。只添加自己负责的路径。
8. **失败与自我更正必须留痕**，不得删除或改写历史结论；更正要在原处加显式撤回标注。
