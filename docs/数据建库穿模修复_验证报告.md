# 数据建库穿模缺陷 —— 修复与验证报告

- 对象脚本：`scripts/build_gpcr_v3.py`
- 验证脚本：`scripts/verify_build_pose_fix.py`（离线，不需要网络）
- 指标口径：与 `scripts/diagnose_dataset.py` 完全一致
  - `ligand_min_dist_to_pocket` = 配体重原子到口袋蛋白重原子的最近距离
  - `LIGAND_CLASH_POCKET`：< 0.5 Å（**原子级穿模，属于推荐丢弃**）
  - `LIGAND_CLOSE_CONTACT`：0.5 ~ 1.5 Å
  - `LIGAND_OUTSIDE_POCKET`：落在口袋包围盒（外扩 2 Å）内的重原子占比 < 0.5

---

## 1. 缺陷

原始 `build_gpcr_v3.py` 只从 mmCIF 里取配体的**实验质心**，然后用 SMILES 经 ETKDG
重新生成一个构象、把质心平移到该位置。重建构象的扭转角与实验构象无关，因此配体会
插进蛋白壁。

修复前对已建成的 gpcr_v3 数据集（974 对有效样本）的全量诊断：

| 指标 | 数值 |
|---|---|
| `LIGAND_CLASH_POCKET`（最近重原子距离 < 0.5 Å） | **16.0 %** |
| 数据集内最近重原子距离 | 0.253 – 0.620 Å |
| 同一指标在实验位姿上的取值 | 2.498 / 3.041 / 3.298 / 3.344 Å |
| 部分出袋 / 完全出袋 | 10.8 % / 3.2 % |

即：数据集的配体位置与真实晶体位姿不一致，且 16 % 到了原子重叠的程度。
该数据集已随迭代回退删除，上表为当时的诊断结论，此处作为修复前的基线保留。

## 2. 修复

`parse_cif_once` 除质心外**同时返回各配体的实验原子坐标**；新增
`build_from_experimental(atoms, smiles)`：把实验坐标写成 PDB 块（严格按固定列位），
再由 `AllChem.AssignBondOrdersFromTemplate` 用 SMILES 模板校正键级。

### 2.1 一个不能回避的真实情形

`build_from_experimental` 要求**沉积原子组成与 SMILES 一致**，否则返回
`composition_mismatch`。这不是罕见的边角情况：沉积结构经常漏建个别原子。

实测例子 —— **5UEN 的 DU1**：

| | 重原子数 | 元素组成 |
|---|---|---|
| 沉积坐标（`_atom_site`） | 35 | C24 N5 O5 S1 |
| CCD 定义（SMILES） | 36 | C24 N5 O5 S1 **F1** |

即磺酰氟上的 F 未被建模。这类条目下"使用实验坐标"与"保持 SMILES 指定的完整分子"
**不可兼得**：

- 回退到生成构象 → 配体重新插进蛋白壁（正是本次要修的缺陷）
- 丢弃该样本 → 少一条数据，但留下的一律不穿模

因此新增 `--on-mismatch {skip,fallback}`：**默认 `skip`（丢弃）**，`fallback` 保留
修复前的旧行为以便对照。所有被丢弃的配体会写进 `<out>/unusable_ligands.csv`
（含沉积/模板重原子数与差值），便于人工复核。

### 2.2 顺带修掉的可复现性缺陷

`base_index()` 原用内置 `hash(pid)`。Python 对 `str` 的 `hash` 带**进程随机盐**
（`PYTHONHASHSEED`），导致回退构象的随机种子每次运行都不同、同一份输入建出的数据集
随之变化。已改为 `zlib.crc32`。

该缺陷是验证过程中暴露的：同一命令两次运行，旧路径的最近重原子距离从
0.760/0.481 变为 0.574/1.171。修复后两次运行逐位一致。

## 3. 验证

### 3.1 逐样本对照（真实 RCSB 数据，离线）

用本地 3 个真实 GPCR-配体复合物的完整 mmCIF；配体 SMILES 从条目自带的 CCD 块
（`_chem_comp_atom` / `_chem_comp_bond`）提取，与流水线用的
`rcsb_chem_comp_descriptor` 同源。

| 结构/配体 | 路径 | 最近重原子距离 | 相对实验位姿坐标偏差 | 判定 |
|---|---|---|---|---|
| 3PBL / ETQ | EXP | 2.702 Å | 0.0000 Å | — |
| | **NEW** | **2.702 Å** | **0.0000 Å** | — |
| | OLD | 0.574 Å | 6.9530 Å | CLOSE_CONTACT |
| 4IB4 / ERM | EXP | 2.630 Å | 0.0000 Å | — |
| | **NEW** | **2.630 Å** | **0.0000 Å** | — |
| | OLD | 1.171 Å | 11.7004 Å | CLOSE_CONTACT |
| 5UEN / DU1 | EXP | 1.612 Å | 0.0000 Å | — |
| | NEW | — | — | `composition_mismatch` → 弃用 |
| | OLD | 0.581 Å | — | CLOSE_CONTACT |

| 路径 | 样本 | 可用 | 弃用 | 可用中穿模(<0.5 Å) | 紧接触(0.5–1.5 Å) |
|---|---|---|---|---|---|
| EXP | 3 | 3 | 0 | 0 | 0 |
| **NEW** | 3 | 2 | 1 | **0** | **0** |
| OLD | 3 | 3 | 0 | 0 | 3 (100 %) |

要点：

- **NEW 的坐标与实验位姿逐原子一致（最大偏差 0.0000 Å）** —— 这是修复成立的直接证据；
  旧路径在同一指标上偏离 7.0 – 11.7 Å。
- 旧路径在本次种子下落在 0.57 – 1.17 Å（全部 `CLOSE_CONTACT`）；换种子可落到 0.48 Å
  （`CLASH_POCKET`）。即旧路径的结果对随机种子敏感，群体层面的穿模率以 16.0 % 为准。
- 本表 n = 3，样本量小，**不能**用来估计修复后的群体穿模率；群体结论需要全量重建。

### 3.2 流水线级对照（同一份输入，两种策略）

```
python scripts/build_gpcr_v3.py --src <smoke> --out data/_v3_smoke_out --min-samples 2
python scripts/build_gpcr_v3.py --src <smoke> --out data/_v3_smoke_out_fb --min-samples 2 --on-mismatch fallback
python scripts/diagnose_dataset.py --data <out> --mask-samples 0
```

| 产出 | 样本 | 实验坐标 / 回退生成 | 诊断异常样本 | 三档过滤规则的 drop 率 |
|---|---|---|---|---|
| `_v3_smoke_out`（默认 skip） | 2 | 2 / 0 | **0（0.00 %）** | 全部 0 % |
| `_v3_smoke_out_fb`（fallback） | 3 | 2 / 1 | **1（33.33 %）** | aggressive 档 33.33 % |

`fallback` 保留的那条样本，正是诊断工具标记为 `LIGAND_CLOSE_CONTACT` 的
`lig_5UEN_DU1.sdf`。即：**默认策略产出的数据集在该诊断下是干净的**。

同时确认产出格式正确：`index.pkl` 为 4 元组、`split_by_name.pt` 含 train/test、
`build_report.txt` 记录 `experimental_pose` / `fallback_generated` / `composition_mismatch` /
`unusable_reasons`，`unusable_ligands.csv` 记录 `5UEN,DU1,35,36,1`。

## 4. 结论与边界

**已成立**

1. 修复使配体坐标逐原子等于实验位姿（偏差 0.0000 Å），从机制上消除了"重建构象只平移
   质心"导致的穿模。
2. 组成不匹配的条目不再被静默回退到会穿模的路径，而是默认丢弃并留痕。
3. 建库随机种子可复现。
4. 流水线端到端可跑通，产出的数据集在项目自带诊断下 0 异常。

**尚未验证（需要网络，本次断网无法执行）**

- 全量重建（738 结构 / 1009 配体对）后，穿模率从 16.0 % 降到多少。
- 组成不匹配在全体数据中的实际占比；据此判断丢失的样本量是否可接受。
  若占比偏高，需评估 `--on-mismatch perceive`（按几何推断键级、保留沉积坐标）是否值得引入。
- 合并进 `gpcr_multitarget_v2` 后的端到端训练验证。

**未改动**

- 权重 `ckpt/pretrained_Pocket2Mol.pt` 仍为官方权重，本次修复不涉及模型。
- 数据集扩容产出的数据本身（随上一次迭代回退已删除），本次只修复建库脚本。

## 5. 复现方式

```
# 逐样本对照（需要本地有真实 mmCIF；默认指向 data/targets）
python scripts/verify_build_pose_fix.py

# 流水线冒烟（自备含 <pid>.cif 与 pairs.csv 的目录）
python scripts/build_gpcr_v3.py --src <dir> --out data/_v3_smoke_out --min-samples 2
python scripts/diagnose_dataset.py --data data/_v3_smoke_out --mask-samples 0
```
